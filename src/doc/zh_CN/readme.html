这个插件可以做什么

LION是一款插件，能够按照特定的时间间隔，对屏幕上特定的区域进行自动光学字符识别（OCR）操作。

为什么说它智能呢？这既不是因为它是我编写的，也不是因为“i”让这个首字母缩写显得很巧妙。

由于它会对同一屏幕区域进行多次OCR操作，正常情况下，它会多次读取到相同的文本，这显然不太理想。因此，我实现了一种机制，当识别出的文本与之前识别的文本相似时，就不再进行朗读。并且增加了使用正则过滤识别结果的功能。

我能用它做什么

编写这款插件的主要目的是为了读取字幕。基于其工作原理，它可以读取屏幕上的各类字幕，包括YouTube、Netflix、哔哩哔哩等在线视频网站上的字幕，AVI文件中嵌入的字幕，甚至是直播电视的字幕！

在使用时，务必将视频设置为全屏模式，因为它的工作方式类似于正常人的视觉。较大的文本有助于它获得更好的识别效果。不过，识别质量并非完美无缺。如果可以设置，尽量将字幕字体调大，并使用高分辨率屏幕。它所采用的OCR引擎并非十全十美，在某些图像上的识别效果可能不太理想。

除了读取字幕，它还能用于监测屏幕上那些无法直接访问的文本，比如视频游戏的菜单。但遗憾的是，它无法识别高亮显示的文本。

我该如何使用它

若要使用默认选项启动该插件，只需按下NVDA + ALT + N组合键。LION便会每隔1秒对整个屏幕进行一次OCR操作，且只有在文本发生变化时才会进行朗读。希望能如你所愿。

如果你想对其功能进行自定义设置，可以前往NVDA菜单，进入“选项”，再选择“设置”，找到“lion类别”。例如，视频文件的左上角可能会有一个标识，在读取字幕后，这个标识也会被一并读出，从而影响使用体验。下一部分我们将介绍如何解决这个问题。

LION具备以下设置项：

  1. 识别间隔：即程序执行OCR操作的频率，取值范围为0.1秒至10秒。
  2. 识别目标：用于指定进行OCR操作的屏幕区域。可供选择的选项包括：当前控件、当前窗口、导航对象以及全屏。
  3. 从上方、下方、右侧、左侧裁剪像素：在全屏模式下，这四个设置项可用于裁剪屏幕中不需要扫描的区域。此设置仅在全屏模式和当前窗口模式下生效。这个设置有什么用呢？以之前提到的标识为例，只需从上方裁剪大约10%左右的区域，就能跳过这个标识，避免它被读出。实际上，为了加快识别速度并减少资源占用，你可以从上方裁剪大约70%的区域，因为字幕通常位于屏幕下方三分之一的位置。

写在前面

本修改版保留了原版的核心体验。区域管理支持多选区与裁剪，朗读调度支持排队，让屏幕上的字幕和对话更稳定、更省心地读出来。

使用前：准备 OCR 服务

本插件需要自行准备可用的 PaddleOCR HTTP 服务。推荐在本机部署，延迟低，令牌不必出本机。下文以 http://127.0.0.1:23353 为例，请按实际部署替换地址、端点与令牌。

这里的“模型”指 OCR 端点，而不是服务端可切换的模型参数；服务端能提供哪些端点，取决于它的部署配置。常见端点示例：

  • /ocr：快速档，适合屏幕字幕、游戏界面等常规识别。
  • /ocr-acc：精确档，耗时更长。
  • /layout-parsing：版面解析（PaddleOCR-VL），适合整页文档。

以上仅作常见端点示例，具体以你的服务为准。

在 NVDA 菜单 → 选项 → 设置 → LION 修改版 中填写：

  • OCR 服务地址：初始值 http://127.0.0.1:23353，只填基址，不带端点。
  • 模型 / 端点：初始值 /ocr；也可以填其他常见端点（如 /ocr-acc、/layout-parsing）、自定义路径或完整 URL。
  • 服务令牌：按实际部署填写；留空则不发鉴权头。

服务地址是基址，模型是端点，两者拼起来才是最终请求地址；若模型填的是完整 URL，则直接按该 URL 请求。

填好后按 测试 / 获取模型：先探活，再读取模型列表，然后校验令牌，最后对快端点做一次识别测试，结果显示在按钮下方。

怎么用 / 识别区域

按 NVDA+Alt+N 开始或停止。插件会按识别间隔，对所有已勾选的区域各识别一次，只在文本变化时朗读。

在“设置 → LION 修改版”中有一个区域列表，三列分别是区域名 / 识别目标 / 裁剪：

  • 勾选框：用空格键或鼠标点击勾选、取消勾选。只有被勾选的区域参与识别；取消勾选只是暂时停用，配置仍然保留。
  • 添加 / 编辑 / 删除：用对应按钮增删改；选中一行按回车也能编辑，修改后列表立即刷新。
  • 顺序：用“上移 / 下移”调整；列表顺序就是排队朗读的顺序。
  • 批量：用“全部启用 / 全部停用”一次性切换勾选状态。
  • 识别目标：每个区域可单独选择当前对象、全屏幕、当前窗口或当前控件。
  • 裁剪：从目标矩形里裁掉多少百分比（上和左是偏移，下和右是收缩）。例如“全屏幕 + 从上方裁剪 70%”就是屏幕下方 30% 的横向长条，正适合字幕。
  • 上下裁剪之和、左右裁剪之和都不能超过 100%，编辑对话框会直接拦住非法组合。

建议：字幕场景只勾选一到两个“字幕条”区域，并把上方裁剪到 70% 左右。区域越少、面积越小，一轮识别越快，也越不容易读出无关文字。

旧配置迁移：从旧版升级时，原有的“识别目标 + 四向裁剪”会在首次启动时自动变成一个区域（名为“区域 1”），识别范围与原来一致，不需要手动设置。

热键冲突

原版 LION 与本插件都使用 NVDA+Alt+N。两个插件同时启用时，这个热键是冲突绑定，按下去无法预期触发哪个。解决办法二选一：

  • 只留一个：NVDA 菜单 → 选项 → 输入手势 → 找到原版 LION 的“开关OCR” → 在“按键”列表里选中 NVDA+Alt+N → 按“清除”。
  • 各给一个：在“输入手势”里给本插件或原版的“开关OCR”另绑一个组合键。

去重方式

原版按相似度去重，假设“文本一次显示完整”，适合影视字幕；但 RPG 对话是逐字出现的，每一帧都是上一帧的延长，相似度一路升高，整句很容易被判定为“没变”而漏读。因此，本插件把去重方式做成按区域可选项：

去重方式 适合场景 行为
经典（相似度）初始值 影视字幕、整行一次性显示的文字 与上一句相似度低于阈值才念（原版行为）
稳定后念一次 RPG 对话、打字机效果 等文字不再增长后，整句念一次
跟读增量 很长的对话（10 秒以上） 按标点分段，边说边出
关闭（每次变化都念） 排障 每次变化都念

设置位置：设置 → LION 修改版 → 选中某个区域 → 编辑…，对话框底部有去重方式、稳定阈值（毫秒）与经典相似度阈值。

  • 稳定阈值（毫秒）：初始值 1500，范围 500–10000。打字快时可调小（如 800），朗读更及时；打字慢或 OCR 偶尔抖动时可调大（如 2500），避免把半句当成整句。
  • 经典相似度阈值（%）：只在“经典（相似度）”下生效，默认勾选“使用全局相似度阈值”（即主设置里的默认值）。取消勾选后可按区域单独设置 0–100。语义是：与上一句的相似度低于该值才朗读，所以数值越低越严格、越高越容易念；数字/模板类变化（例如“第1回合” → “第2回合”）相似度高，想读到就把该区域的阈值调高。
  • 游戏场景建议：对话区域选“稳定后念一次”，阈值 1500；长对话一次显示很多字时改用“跟读增量”。

每个区域独立配置。常见组合是：字幕条用“经典（相似度）”，RPG 对话框用“稳定后念一次”，长文本或日志区用“跟读增量”，排障区域用“关闭”。去重决定念什么，排队朗读决定怎么排，两者互不冲突。

排队朗读

设置中有一个复选框：排队朗读（多区域时建议开启）。

关闭（初始值） 开启

单区域时的行为 与旧版完全一致 与旧版完全一致

配置档案（Profile）

  • NVDA 2026.3 或更高：本插件的设置固定保存在基础配置，不随配置档案（Profile）或触发器变化。切换档案时语音行为不会改变；保存设置也只写基础 nvda.ini。
  • 首次安装/升级后需要重启 NVDA 才会切换为这种全局模式；若旧版本曾在配置档案里保存过本插件设置，这些值会被忽略，必要时应重新保存一次设置。
  • NVDA 2026.1/2026.2：没有相应 API，插件仍会随活动配置档案变化；建议在基础配置（不激活任何档案）下修改设置。

设置项

以下只列其它设置与识别参数。区域列表见“怎么用 / 识别区域”，去重方式、稳定阈值与逐区域阈值见“去重方式”，排队朗读与合并区域截图见前两节，配置档案见上一节，不再重复。

其它设置

  1. 请求超时（毫秒）：初始值 15000；字幕条识别通常只需几十毫秒，网络差或服务忙时可加大。
  2. 图像格式：JPEG（初始值，更小更快）或 PNG（无损但更大）。
  3. 返回可视化图：关闭（初始值）。开启后服务端要画框并编码图片，耗时明显增加，不建议日常开启。
  4. 最低识别分数（%）：初始值 0，即不额外过滤。调高可挡掉低置信度的乱码；服务端本身也会过滤空文本。
  5. 检测最长边：初始值 0，表示使用服务端配置。
  6. OCR 服务不可用时提示一次错误：开启（初始值）。服务不可用时每个区域只提示一次，之后写日志，避免刷屏。
  7. 合并区域截图：关闭（初始值）。开启后把所有勾选区域一次抓下来再本地裁剪，减少抓屏次数；区域相隔很远时可能更慢，详见上一节。

识别参数（与原版一致）

  1. 识别间隔（毫秒）：OCR 执行频率，100 毫秒到 10 秒。多区域时一轮总耗时会相加；如果一轮超过间隔，下一轮会紧接着开始，不会重叠。
  2. 默认文本相似度阈值（%）：初始值 50，作为“经典（相似度）”的默认值；每个区域可在编辑对话框里单独覆盖（见“去重方式”）。语义：相似度低于阈值才朗读，数值越低越严格；只影响“经典”，不影响“稳定后念一次”“跟读增量”“关闭”。
  3. 识别内容过滤（正则）：每行一条正则，匹配到的内容会从识别结果里删掉，对所有区域生效。注意：识别结果会先拼成一行，所以行锚点 ^、$ 匹配不到单个识别行；要删整行请直接用关键词（如 赞助商消息），或写 [^\s]*关键词[^\s]*。删完留下的多余空格会自动折叠。

已知限制

  • 文字顺序：读到的行按检测顺序拼接，不保证是阅读顺序。字幕场景影响不大；整页文档建议改用服务端的版面解析端点（如 /layout-parsing）。
  • 必须依赖外部服务：服务没启动时本插件不可用（每个区域会提示一次错误并写日志）。
  • 不支持文档解析：本插件只对接屏幕内容 OCR；整页文档转 Markdown 属于另一条产线，未纳入。
  • 部分参数不适用于版面解析端点：如“检测最长边”“最低识别分数”等由服务端决定，具体以你的服务为准。
  • 区域数量会线性影响一轮耗时：区域越多、越大，一轮越慢，请只勾选真正需要的区域。

故障排查

现象 处理
提示“OCR 服务不可用” 确认服务仍在运行；访问示例地址的 /health（如 http://127.0.0.1:23353/health）应返回正常状态
提示未授权（HTTP 401） 服务令牌不正确；重新填写，注意不要带首尾空格或换行
服务返回 HTTP 400 请求带了该端点不支持的能力开关，日志里会有服务端提示与 supportedFlags
请求超时 服务忙或图太大；调大“请求超时”、裁剪区域，或改用 JPEG
什么都不朗读 检查是否一个区域都没勾选；检查“默认文本相似度阈值”是否过低（越低越严格；0 时几乎不念）；检查裁剪是否把字幕裁掉
某个区域不播报 先看该区域的去重方式：经典模式下变化文本与上次播报太相似会被跳过（数字/模板变化常见，可在区域编辑里调高该区域阈值）；稳定后朗读/跟读增量需要等文字稳定或出现标点；未开“排队朗读”时一轮只念最后一个有变化的区域。需要细节可把 NVDA 日志级别调成 debug，插件会按区域输出有效阈值与判定结果
设置不随配置档案变化 这是 3.3.8 起的预期行为（NVDA 2026.3+）：插件配置固定在基础配置；旧版本仍会随档案变化
只朗读一个区域 未开启“排队朗读”时，一轮只朗读最后一个有变化的区域；需要每个区域都念请开启排队朗读
按热键没反应 多半是热键冲突，见“热键冲突”
提示黑屏 使用 OCR 前请先关闭黑屏（screen curtain），这是 NVDA 的限制
