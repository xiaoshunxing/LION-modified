这个插件可以做什么

LION是一款插件，能够按照特定的时间间隔，对屏幕上特定的区域进行自动光学字符识别（OCR）操作。

为什么说它智能呢？这既不是因为它是我编写的，也不是因为“i”让这个首字母缩写显得很巧妙。

由于它会对同一屏幕区域进行多次OCR操作，正常情况下，它会多次读取到相同的文本，这显然不太理想。因此，我实现了一种机制，当识别出的文本与之前识别的文本相似时，就不再进行朗读。并且增加了使用正则过滤识别结果的功能。

我能用它做什么

编写这款插件的主要目的是为了读取字幕。基于其工作原理，它可以读取屏幕上的各类字幕，包括YouTube、Netflix、哔哩哔哩等在线视频网站上的字幕，AVI文件中嵌入的字幕，甚至是直播电视的字幕！

在使用时，务必将视频设置为全屏模式，因为它的工作方式类似于正常人的视觉。较大的文本有助于它获得更好的识别效果。不过，识别质量并非完美无缺。如果可以设置，尽量将字幕字体调大，并使用高分辨率屏幕。它所采用的OCR引擎并非十全十美，在某些图像上的识别效果可能不太理想。

除了读取字幕，它还能用于监测屏幕上那些无法直接访问的文本，比如视频游戏的菜单。但遗憾的是，它无法识别高亮显示的文本。

我该如何使用它

若要使用默认选项启动该插件，只需按下NVDA + ALT + N组合键。LION便会每隔1秒对整个屏幕进行一次OCR操作，且只有在文本发生变化时才会进行朗读。希望能如你所愿。

如果你想对其功能进行自定义设置，可以前往NVDA菜单，进入“选项”，再选择“设置”，找到“lion类别”。例如，视频文件的左上角可能会有一个标识，在读取字幕后，这个标识也会被一并读出，从而影响使用体验。下一部分我们将介绍如何解决这个问题。

LION具备以下设置项：

  1. 识别间隔：即程序执行OCR操作的频率，取值范围为0.1秒至10秒。
  2. 识别目标：用于指定进行OCR操作的屏幕区域。可供选择的选项包括：当前控件、当前窗口、导航对象以及全屏。
  3. 从上方、下方、右侧、左侧裁剪像素：在全屏模式下，这四个设置项可用于裁剪屏幕中不需要扫描的区域。此设置仅在全屏模式和当前窗口模式下生效。这个设置有什么用呢？以之前提到的标识为例，只需从上方裁剪大约10%左右的区域，就能跳过这个标识，避免它被读出。实际上，为了加快识别速度并减少资源占用，你可以从上方裁剪大约70%的区域，因为字幕通常位于屏幕下方三分之一的位置。

3.3.6 新增：自定义模型（OCR 端点）与"测试 / 获取模型"

先说清楚"模型"是什么

本插件的后端 PaddleOCR 服务是单端口挂多条产线：/ocr（PP-OCRv6 快速档）、/ocr-acc（精确档，需服务端开启）、 /layout-parsing（PaddleOCR-VL）。服务端没有"模型参数"，模型/产线是启动时配置决定的，客户端能选的是打哪个端点。 所以本插件里的"模型"就是 OCR 端点：默认 /ocr，也可以填 /ocr-acc、/layout-parsing、任意自定义路径， 甚至一个完整 URL（把"模型"指向另一台机器上的服务）。

> 服务地址与模型/端点分开填写：地址是基址（例如 http://127.0.0.1:23353），模型是端点（例如 /ocr）， > 拼起来才是真正请求的地址。从 3.3.5 升级的老配置会在首次启动时自动迁移，最终请求地址与原来完全一致。

"测试 / 获取模型"按钮做了什么

一个按钮按顺序完成四件事，并在下方文字里逐项报告：

  1. 探活：访问 /health，确认服务在运行；
  2. 获取模型列表，按"通行程度"依次尝试：
  • GET /models —— OpenAI 风格的模型列表（若服务提供，会用其中的 endpoint 字段定位真正端点）；
  • GET /v1/models —— OpenAI 兼容实现；
  • GET /openapi.json —— 兜底：当前这个 PaddleOCR 服务没有 /models，所以会走这一级，

把 OpenAPI 里带 POST 的端点当"可用模型"，界面会明确标注"列表来源：OpenAPI 端点列表"。

  1. 校验令牌：发一个缺 file 的请求体，令牌错会得到 401、令牌对会得到 400/422 —— 不会触发真正的识别，

所以很快，对 PaddleOCR-VL 也是毫秒级；

  1. 识别测试：对快端点发一张 8×8 小图验证真的能识别；选中 /layout-parsing 时跳过这一步并提示，

因为 PaddleOCR-VL 单次推理要 3 秒以上，容易误报超时。

组合框可以编辑：列表里没有的端点，直接手动输入即可。

用 PaddleOCR-VL（/layout-parsing）要注意

  • 它本来是文档解析，速度比 PP-OCRv6 慢一个量级；请把"请求超时"调大（默认 15 秒可能不够，上限 120 秒）。
  • 插件只取它的"文本"（按版面块顺序），不处理表格/公式/图表/印章等结构；这些块会被跳过。
  • "检测最长边""最低识别分数"等设置对 /layout-parsing 不生效（服务端会忽略），保持默认即可。

3.3.5 修复了什么（真机反馈）

3.3.4 之后 稳定后朗读 已经好了，但 跟读增量 在句子念完安定下来之后又会重复播报。3.3.5 已修。

原因有两个，叠加在一起：

  1. 判断"这一帧和上一帧是不是同一句"时用了"公共前缀占比"。

长台词里只要错字出现在靠前的位置（例如第 3 个字），占比就会很低（3/26）， 于是被判成"换了一句新台词"。

  1. 跟读增量 一看到"换了一句"就把"已经念到哪"的记录清空，于是从第一个字重念。

（稳定后朗读 有"这句刚念过"的兜底，所以只有跟读模式暴露这个问题。）

3.3.5 的改法：

  • 抖动判定改为按长度自适应的编辑距离：短句容忍 1 处识别差异，长句（12 字以上）容忍 2 处，

不再看"公共前缀占多少"。

  • 新增模糊锚点：已播报的内容就算中间错了一个字，也能在新文本里定位到正确的续读位置，

只念后面新增的部分。

  • 跟读补上与"稳定后朗读"相同的"已播报内容相似度"兜底。
  • 纯标点片段（例如末尾突然多出来的 ！）不再被单独念出来。
  • 数字/编号变化（第1帧→第2帧、HP: 100→HP: 90）明确按新内容处理，不会被当成抖动吞掉。

修好后的预期听感：长对话跟读时一句一句往外冒；整段讲完后停在屏幕上， 即使 OCR 偶尔认错一个字，也不会再从头念一遍。

3.3.4 修复了什么（真机反馈）

3.3.3 的两套新模式在真实游戏里有两个体验问题，3.3.4 已修：

  1. "稳定后朗读"打完一句后会重复播报同一句。

原因是真实 OCR 每帧都会抖（少一个标点、多一个空格、偶尔认错一个字、甚至整帧读空）， 旧实现把任何差异都当成"换了一句"，于是把"已经念过什么"的记录清空，稳定下来后再念一遍。 现在会先把每一帧分类成"同一句 / 抖动 / 增长 / 换新句"， 抖动不会清空已播报记录，所以同一句只会念一次。

  1. "跟读增量"每段都从头念。

旧实现用"上一帧的完整文本"做位置锚点，帧一抖锚点就归零，于是从第一个字重念。 现在改用"已经播报出去的内容"做锚点，只会念新增的片段。

  1. 顺带修掉：长句逐字打字超过 10 秒时会被保护机制打断，念出没打完的半句。

现在只有内容真的不再增长时才会兜底。

什么情况仍然会重复

  • 对话框真的清空后又显示同一句（游戏循环台词）：这是预期行为，会再念一次。
  • 两个区域框住了同一段文字：两个区域各自去重，所以会各念一次。请只保留一个区域。
  • 同一句在很短时间内被替换成"完全不同"的另一句又换回来：会被当成两句话各念一次。
  • 只差一个数字的变化（如"第1帧"→"第2帧"）按新内容处理，不会被抖动逻辑吞掉。

与 3.3.2 的差别（先看这段）

每个识别区域多了一个去重方式下拉框。默认仍是"经典（相似度）"，所以影视字幕的用法与之前完全一样； 玩 RPG 时把对话区域改成"稳定后念一次"即可。

去重方式 适合场景 行为
经典（相似度）默认 影视字幕、整行一次性显示的文字 与上一句相似度低于阈值才念（原版行为）
稳定后念一次 RPG 对话、打字机效果 等文字不再增长后，整句念一次
跟读增量 很长的对话（10 秒以上） 按标点分段，边说边出
关闭 排障 每次变化都念

为什么需要新的去重方式

原有去重假设"文本一次显示完整"（影视字幕）。但 RPG 对话是一个字一个字出现的， 每一帧都是上一帧的延长，相似度一路升高，于是第一帧念出"你"之后，整句就被判定为"没变"而再也不念。

实测（本机、默认阈值 0.5）：

帧 识别到的文本 与上一帧相似度 经典策略
1 你 0.00 念出"你"
2 你好 0.67 跳过
3 你好冒 0.80 跳过
… … … …
9 你好冒险者欢迎来到 0.94 跳过
12 你好冒险者欢迎来到新手村 0.96 跳过

结果：整句只念出了第一个字，剩下的全丢。新的"稳定后朗读"策略把这条时间线变成： 打字过程中不读，打完后整句读一次。

去重方式怎么调

设置 → LION 修改版 → 选中某个区域 → 编辑…，对话框底部有：

  • 去重方式：四选一，见上表。
  • 稳定阈值（毫秒）：默认 1500，范围 500–10000。
  • 打字很快时可以把阈值调小（如 800），读完更及时；
  • 打字很慢、或 OCR 偶尔抖动时可以调大（如 2500），避免把半句当成整句念出来。

游戏场景推荐：对话区域选"稳定后念一次"，阈值 1500； 如果游戏里的长对话一次显示很多字、要等很久才念完，改用"跟读增量"。

一个区域一个策略

去重方式是按区域配置的，所以常见组合是：

区域 去重方式 理由
字幕条（影视） 经典 整行瞬间出现，原行为最合适
对话框（RPG） 稳定后念一次 逐字出现，等打完再念
长文本/日志区 跟读增量 内容持续增长，边出边念
曾用来排障的区域 关闭 确认 OCR 内容是否在变

配合"排队朗读"：去重决定念什么，排队决定怎么排，两者互不冲突。

其他行为细节

  • 对话框清空后再出现同一句（游戏里循环对话）：会重新朗读。
  • 逐行追加（第 1 行先出现、再出现第 2 行）：只朗读新增的第 2 行，不会重念第 1 行。
  • 整句被替换：按新文本完整朗读。
  • 文字一直变个不停（屏幕上有动画/滚动条）：最多等 10 秒会强制朗读一次，不会一句都不念。
  • 从 3.3.2 升级：已有区域的去重方式自动是"经典"，不需要改任何设置。

使用前：先启动外部 OCR 服务

本插件不自带识别引擎，必须先有一个可用的 PaddleOCR 服务。例如部署在 <服务部署目录>：

  1. 双击 启动PaddleOCR-VL.cmd（或运行 scripts\start_app.ps1），窗口里会打印访问令牌。
  2. 打开 NVDA 菜单 → 选项 → 设置 → LION 修改版，填写：
  • OCR 服务地址：默认 http://127.0.0.1:23353（只填基址，不带端点）
  • 模型 / 端点：默认 /ocr（快速档）；精确档填 /ocr-acc；文档解析填 /layout-parsing
  • 服务令牌：把 config\api_token.txt 里的内容粘进来（服务用 -NoAuth 启动时留空即可）
  1. 按"测试 / 获取模型"按钮：探活 → 读取模型列表 → 校验令牌 → 快端点识别测试，结果写在按钮下方。

地址与模型/端点的写法：

  • http://127.0.0.1:23353 + /ocr → http://127.0.0.1:23353/ocr（默认，快速档）
  • http://127.0.0.1:23353 + /ocr-acc → 精确档（需服务端以 -OcrAccurate 启动）
  • http://127.0.0.1:23353 + /layout-parsing → PaddleOCR-VL（慢，记得调大请求超时）
  • 模型也可以直接填一个完整 URL，此时服务地址留空或填任意值都不影响（等于指向另一台机器的服务）

服务在别的机器上时，把地址换成 http://那台机器:23353/ocr 即可（该服务默认监听 0.0.0.0，仅靠令牌保护，请注意网络安全）。

怎么用

按 NVDA+Alt+N 开始或停止。默认每隔 1 秒对所有已勾选的区域各识别一次，只在文本变化时朗读。

例如：勾选"字幕"与"聊天区"两个区域，开启排队朗读，两个区域的新文本会先后来朗读，而不会互相打断。

关于热键冲突（重要）

原版 LION 和本修改版默认都用 NVDA+Alt+N。两个插件同时启用时这个热键是冲突绑定，按下去无法预期触发哪个。解决办法二选一：

  • 只留一个：NVDA 菜单 → 选项 → 输入手势 → 找到原版 LION 的"开关OCR" → 在"按键"列表里选中 NVDA+Alt+N → 按"清除"。
  • 各给一个：在"输入手势"里给本修改版或原版的"开关OCR"另绑一个组合键。

识别区域（多选区）

在"设置 → LION 修改版"里有一个区域列表，三列分别是区域名 / 识别目标 / 裁剪：

  • 勾选框：用空格键（或鼠标点击）勾选/取消勾选。只有被勾选的区域会在启动时被识别；取消勾选等于把它暂时停用，配置仍然保留。
  • 添加：按"添加…"按钮，在对话框里填写区域名、识别目标与四向裁剪百分比，确定即可。
  • 编辑：选中一行按回车（或按"编辑…"按钮）修改；修改后列表立即刷新。
  • 删除：选中一行按"删除"按钮。
  • 顺序：用"上移/下移"调整。列表顺序就是排队朗读的顺序。
  • 批量：用"全部启用/全部停用"一次性切换勾选状态。
  • 每个区域的识别目标可单独选择：当前对象、全屏幕、当前窗口、当前控件。
  • 每个区域的裁剪指从该区域目标矩形里裁掉多少百分比（上和左是偏移，下和右是收缩）。例如"全屏幕 + 从上方裁剪 70%"就是屏幕下方 30% 的横向长条，正是字幕所在的位置。
  • 裁剪的上下之和、左右之和都不能超过 100%；编辑对话框会直接拦住非法组合。

建议：字幕场景只勾选一到两个"字幕条"区域，并把上方裁剪到 70% 左右。区域越少、面积越小，一轮识别越快，也越不容易把无关文字读出来。

旧配置会自动迁移

如果你从 3.3.1 或原版升级，旧的"识别目标 + 四向裁剪"会在首次启动时自动变成一个区域（名字为"区域 1"），识别范围与原来完全一致，不需要手动设置。

排队朗读

设置里有一个复选框：排队朗读（多个区域时建议开启）。

关闭（默认） 开启
多区域时的行为 打断式：一轮里只朗读最后一个有变化的区域的文本 按列表顺序把每个有变化的区域的文本依次排队朗读，互不打断
单区域时的行为 与旧版完全一致 与旧版完全一致
实现方式 NVDA 的"立即朗读"优先级（会打断正在朗读的旧内容） NVDA 的"下一句"优先级（等上一句读完再读）

注意：开启排队朗读后，如果你识别到一半就按 NVDA+Alt+N 停止，已经排进队列的文本还会继续念完；插件被禁用或 NVDA 退出时会清空队列。

设置项

识别区域

  1. 识别区域列表：见上一节（勾选框 = 是否参与识别）。
  2. 去重方式：每个区域四选一，见"去重方式怎么调"。
  3. 稳定阈值（毫秒）：只对"稳定后朗读/跟读增量"生效，默认 1500。
  4. 排队朗读：见上一节。

外部服务相关

  1. OCR 服务地址：见上（服务基址，不带端点）。
  2. 模型 / 端点：可编辑组合框。默认 /ocr；按"测试 / 获取模型"后会用服务端实际返回的模型列表刷新候选。也可以直接输入任意路径或完整 URL。
  3. 服务令牌：见上。以密码形式显示；留空则不发鉴权头。
  4. 请求超时（毫秒）：默认 15000。字幕条识别实测只需几十毫秒，余量很充足；网络差或服务忙时可加大。
  5. 图像格式：JPEG（默认，更小更快）或 PNG（无损但更大）。本机 4K 全屏实测：PNG 约 364 ms、JPEG 约 339 ms。
  6. 返回可视化图：默认关闭。开启后服务端要画框并编码图片，实测 4K 全屏从约 0.34 秒涨到约 2.0 秒，不建议开。
  7. 最低识别分数（%）：默认 0，即不额外过滤。调高可把低置信度的乱码挡掉（服务端本身也会过滤空文本）。
  8. 检测最长边：默认 0，表示"用服务端配置"。本机实测传 1280 并没有变快，所以默认不发送。
  9. OCR 服务不可用时提示一次错误：默认开启。服务不可用时每个区域只提示一次，之后写日志，避免每秒刷屏。

识别参数（与原版一致）

  1. 识别间隔（毫秒）：OCR 执行频率，100 毫秒到 10 秒。多区域时一轮总耗时会相加，如果一轮超过间隔，下一轮会紧接着开始，不会重叠。
  2. 文本相似度阈值（%）：默认 50，用来判断"文本有没有变"；每个区域单独比较。
  3. 识别内容过滤（正则）：每行一条正则表达式，匹配到的内容会从识别结果里删掉，对所有区域生效。注意：识别结果会先被拼成一行，所以行锚点 ^ 和 $ 匹配不到单个识别行——要删掉整行内容请直接用关键词（如 赞助商消息），或写 [^\s]*关键词[^\s]*。删完留下的多余空格会被自动折叠。

性能实测（本机 3840×2160，含 base64 与 HTTP 往返）

单个区域的端到端耗时：

截图范围 图像格式 端到端耗时（p50）
全屏 3840×2160 JPEG 301.6 ms
全屏 3840×2160 PNG 472.1 ms
1920×1080 区域 JPEG 141.9 ms
字幕条 3840×540 JPEG 79.3 ms
字幕条 3840×259 JPEG 29.7 ms
全屏 + 可视化图 JPEG 约 2000 ms

多区域时的总耗时 ≈ 各区域耗时之和（一次只发一个请求）。例如"字幕条 + 聊天区"两个小区域大约 100–150 ms，仍然远快于 1 秒的默认间隔。

建议：识别字幕时务必裁剪出字幕条区域，既能显著提速，也能减少无关文字被读出来。

已知限制

  • 文字顺序：读到的行按检测顺序拼接，不保证是阅读顺序。字幕场景影响不大；整页文档建议改用服务端的 /layout-parsing 接口。
  • 必须依赖外部服务：服务没启动时本插件不可用（每个区域会提示一次错误并写日志）。
  • 不支持文档解析：本版本只对接 POST /ocr（屏幕内容 OCR）。整页文档转 Markdown 属于另一条产线，未纳入。
  • 区域数量会线性影响一轮耗时：区域越多、越大，一轮越慢；请只勾选真正需要的区域。

常见问题

现象 处理
提示"OCR 服务不可用" 确认服务窗口还开着；访问 http://127.0.0.1:23353/health 应返回 Healthy
提示未授权（HTTP 401） 令牌不对。重新从 config\api_token.txt 复制（注意不要带首尾空格或换行）
服务返回 HTTP 400 请求带了该端点不支持的能力开关，日志里会有服务端提示与 supportedFlags
请求超时 服务在忙或图太大；调大"请求超时"、裁剪区域、或改用 JPEG
什么都不朗读 检查区域列表里是否一个都没勾选；检查"相似度阈值"是否过高；检查各区域裁剪是否把字幕裁掉了
只朗读一个区域 未开启"排队朗读"时，一轮只朗读最后一个有变化的区域；需要每个区域都念请开启排队朗读
按热键没反应 多半是热键冲突，见上文"关于热键冲突"
提示黑屏 使用 OCR 前请先关闭黑屏（screen curtain），这是 NVDA 的限制
