# 发布流程

> 代理/自动化维护请先读 [AGENTS.md](../AGENTS.md)（唯一权威工作流）；本文只保留人工发布细节。

适用于维护者。当前公开版本：**3.3.8**；版本规则：主版本沿用上游 **3.3**，修改版用 **3.3.N** 递增。
**正确顺序：改版本 → 打包 → 全量测试（含包级用例）→ 提交/tag → Release。**
先测试后打包会静默跳过 22 项包级用例（版本号、条目清单、体积、`src/` 与产物一致性；test_package 18 项 + lite bundle 4 项）。

## 1. 改版本

先把下面所有位置里的旧版本号改掉（建议改完用 `git grep -n '3\.3\.8'` 再核对一遍）：

- `src/manifest.ini` 的 `version` 与 `changelog`；
- `src/locale/zh_CN/manifest.ini` 的 `changelog`；
- `src/locale/zh_CN/LC_MESSAGES/nvda.po` 的 `Project-Id-Version`（界面字符串有增删时同步 `.po` 并重编 `.mo`）；
- `variants/lite/src/manifest.ini`、`variants/lite/src/locale/zh_CN/manifest.ini`、
  `variants/lite/src/locale/zh_CN/LC_MESSAGES/nvda.po`；
- `src/doc/zh_CN/readme.md`、`src/doc/en/readme.md` 与 lite 对应 readme（HTML 由打包脚本重新生成）；
- `CHANGELOG.md` 与新建的 `docs/release-notes/v<version>.md`；
- `README.md`、`CONTRIBUTING.md`、`SECURITY.md` 中的版本引用；
- `docs/发布流程.md`、`docs/开发文档-中文.md`、`docs/DevGuide-EN.md` 中的版本引用；
- `tests/test_package.py` 的 `EXPECTED_VERSION`、`tests/test_manifest_and_config.py` 的版本断言、
  `tests/test_lite_variant.py` 的 `LITE_VERSION`；
- `src/installTasks.py` 与 `variants/lite/src/installTasks.py` 的 `SPEC`（新增配置键时与插件 confspec 同步）；
- 包内文件清单有增删时，同步 `NOTICE.md`。

公开材料只使用 3.3.1–3.3.8 的公开口径（当前版本按实际替换）。

## 2. 打包

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts\build_addon.ps1 -Variant full -Python python
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts\build_addon.ps1 -Variant lite -Python python
```

- 系统执行策略默认拒绝未签名脚本时，必须加 `-ExecutionPolicy Bypass`；
- 解释器可用 `-Python`、`$env:LION_PYTHON` 或 PATH 里的 `python` 指定；
- 打包会重新生成 `src/doc/*/readme.html`、创建 `build/lite/` staging，并写 `dist/` 与 `tests/artifacts/`；
- 失败路径只覆盖 `dist/` 里的同名包，不删除其它历史包（发版前建议先备份 `dist/`）。

产物在 `dist/`：

- `LION-modified-<version>.nvda-addon`
- `LION-modified-<version>.files.txt`
- `LION-modified-lite-<version>.nvda-addon`
- `LION-modified-lite-<version>.files.txt`

检查：包内无 `PaddleOCR/`、`PIL/`、`__pycache__`、个人绝对路径、令牌或内部开发编号。

## 3. 测试（打包之后）

```powershell
$env:PYTHONIOENCODING = 'utf-8'
$env:PYTHONDONTWRITEBYTECODE = '1'
$env:LION_SKIP_SERVICE_PROBE = '1'
$env:LION_TEST_LIVE = '0'
python -m unittest discover -s tests -p 'test_*.py'
```

- 完全离线；在线用例的令牌用 `LION_TEST_TOKEN` 或 `LION_TEST_TOKEN_FILE`，不要写进仓库；
- 打包后必须再跑一次：`test_package` 与 lite 产物用例只有 `dist/` 有包时才运行，
  负责校验版本号、条目清单、体积预算与"产物与 `src/` 一致"；
- 记录测试数、通过/跳过数与耗时，写进执行记录。

## 4. 提交与 tag

```powershell
git add -A
git status --short          # 确认不含 dist/、tests/artifacts/、build/、__pycache__
git commit -m "Release LION modified <version>"
git tag -a v<version> -m "LION modified <version>"
git push origin main
git push origin v<version>
```

## 5. 生成源码压缩包与校验值

```powershell
git archive --format=zip --prefix=LION-modified-<version>/ -o dist/LION-modified-<version>-source.zip v<version>
Get-FileHash dist\*.nvda-addon, dist\LION-modified-<version>-source.zip -Algorithm SHA256
```

把包、`.files.txt`、source zip 的 SHA256 写入 `dist/SHA256SUMS.txt`（人工维护，不是 `sha256sum -c` 格式）。

## 6. GitHub Release

1. 打开 `https://github.com/xiaoshunxing/LION-modified/releases/new`；
2. 选择 tag `v<version>`；
3. 标题：`LION 修改版 <version>（完整版 + lite）`；
4. 正文：用 `docs/release-notes/v<version>.md`，包含本版变更与公开版本迭代摘要；
5. 附件：两个 `.nvda-addon`、两个 `.files.txt`、source zip、`SHA256SUMS.txt`；
6. 勾选 latest，发布。

Release 只提供当前版本的安装包；历史版本只展示变更，不附旧包。
发布后从 Release 重新下载附件，核对 SHA256 与体积。

## 7. 归档

把新包与 `.files.txt` 复制到内部资料库 `../LION-opensource/01-发布物/`（仓库外内部资料），
更新 `SHA256SUMS.txt`、`历史版本映射.md` 与执行记录；上一版安装包移入 `01-发布物/历史版本/`。
内部资料库位于公开仓库之外，不提交到公开仓库。

## 8. CI 与后续

- CI（`.github/workflows/tests.yml`）在 Windows runner 上会**先打包再跑全量测试**，
  Python 3.12 / 3.13 双矩阵，因此包级用例在 CI 里也会执行；
- 所有公开文档末尾为 `powered by dsh` 徽章；manifest 与 locale manifest 用纯文本等价行
  `Powered by dsh — https://github.com/deepseek-ai/deepseek-harness`；
- NVDA 插件商店需要单独向 NV Access 申请提交权限；
- 自动 Release 工作流可后续加入，并用下一个 3.3.N 版本验证。
